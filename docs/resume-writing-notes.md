# 이력서 워딩 수정 방향

기존 이력서의 내용 자체는 충분히 좋지만, 일부 문장이 과하게 강한 자기평가처럼 읽힐 수 있었습니다. GitHub 공개 이력서에서는 다음 기준으로 문장을 바꿨습니다.

## 수정 기준

- "혁신적으로", "대폭", "100% 담보" 같은 평가형 표현을 줄이고 실제 행동과 결과를 앞세웠습니다.
- 기술 도입 자체보다 왜 그 선택을 했는지, 어떤 운영 문제를 줄였는지 드러나게 정리했습니다.
- 프로젝트마다 기술 스택, 문제, 행동, 결과가 한눈에 보이도록 같은 형식으로 맞췄습니다.
- 공개 GitHub에 휴대폰 번호를 노출하지 않도록 이메일과 링크 중심으로 연락처를 구성했습니다.
- "AI 도구 도입" 경험은 과장된 리더십 표현 대신 실무 검증과 예산 확보 기여로 낮춰 적었습니다.

## 지원 시 추가하면 좋은 것

- 회사별 JD에 맞춰 Summary 첫 문단과 Core Strengths 순서를 바꾸는 것이 좋습니다.
- 대용량 트래픽/데이터 포지션이면 StepEarth, WECAKE를 위로 강조합니다.
- 플랫폼/연동 포지션이면 MakeON, AI Noon의 이벤트 처리와 인터페이스 조율 경험을 강조합니다.
- 가능하다면 각 프로젝트에 "팀 규모", "담당 범위", "운영 트래픽", "장애/개선 전후 지표"를 1개씩 더 보강하면 서류 통과율이 올라갑니다.
